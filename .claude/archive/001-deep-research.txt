  5. Memory 的具体形式（在选定场景里长什么样）

  以 Mem-0 的 MemoryBank 为蓝本（本地源码 XPolicyLab/policy/Mem_0/Mem_0/source/m
  odels/execution_module/memory_bank/memory_bank.py）。它的具体数据形式是：

  # 每个 episode 一个独立的记忆体
  self.bank = {
    0: {                              # episode_id
      "anchors": [ h_0 ],             # 锚点：任务初始状态的融合隐向量（固定 1 
  帧，永不弹出）
      "window":  [ h_{t-29}, ..., h_t ],  # 滑动窗口：最近 ≤30 
  步操作历史的隐向量（FIFO）
    }
  }

  在 blocks_ranking_rgb 场景下的语义映射：

  ┌───────────────┬────────────────────────────────────────┬───────────────┐
  │    记忆槽     │         存的是什么（具体语义）         │     角色      │
  ├───────────────┼────────────────────────────────────────┼───────────────┤
  │ anchor（锚点  │ 「任务是红/绿/蓝从左到右；三块积木的初 │ 语义/任务意图 │
  │ ）            │ 始位置布局」                           │ 记忆          │
  ├───────────────┼────────────────────────────────────────┼───────────────┤
  │ window（滑动  │ 「我刚抓了红块 →                       │ 情节/过程记忆 │
  │ 窗口）        │ 现在把它往左放」等最近 30 步过程       │               │
  ├───────────────┼────────────────────────────────────────┼───────────────┤
  │ key memory（  │ 「当前子任务 =                         │               │
  │ 规划层，Mn    │ 抓红块」等关键词/子任务映射            │ 高层计划记忆  │
  │ 用）          │                                        │               │
  └───────────────┴────────────────────────────────────────┴───────────────┘

  融合方式：每步用两次串行交叉注意力——当前隐状态先 attend 窗口（最近历史），再
  attend 锚点（初始状态），残差连接。这种「窗口 +
  锚点」双支路结构，就是后续冲突研究的直接抓手。

  6. Memory conflict 的潜力（这是研究价值的核心）

  冲突不是要「造」出来，而是 Mem-0 结构里已经存在、且已有消融证据的三个面：

  1. 窗口 vs 锚点冲突：最近观察（窗口）与初始状态（锚点）矛盾时，两条交叉注意力
     支路读取的是互相冲突的「记忆」，再被残差融合——当前实现没有任何显式冲突消解
     步骤，这就是研究空白。
  2. 冗余/竞争记忆（最强的冲突信号）：RMBench 论文消融明确指出 "anchor memory
     helps when it is the sole carrier of task-relevant history, and hurts when 
     it duplicates higher-level memory" ——去 anchor 使 Swap Blocks 67%→15%，去
     key memory 使 Cover Blocks 68%→5%。即：记忆与更高层记忆重复时反而有害，这正
     是「记忆冲突」可形式化的实验面。
  3. 跨子任务覆盖冲突（Mn 模式）：子任务切换会替换锚点/清空内存（write-write
     冲突），memory_accumulation 阈值决定何时清空——一个天然的超参冲突探针。

  记忆冲突的可度量形式（可直接照搬 RMBench 的方法）：对同一任务跑「完整记忆 vs
  去 anchor vs 去 window vs 去 key」的多路消融，用成功率差量化每个记忆组件的净贡
  献；「组件被移除反而变好」即存在冗余冲突。
