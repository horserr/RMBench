     拆分 RMBench 与 XPolicyLab 的实施计划

     Context（背景与目标）

     当前 XPolicyLab 是 RMBench 的 git submodule（.gitmodules 指向
     horserr/XPolicyLab.git，pin 在 memconflict 分支的
     11efb1db）。两边虽然已经通过 websocket
     在架构上解耦，但代码里残留大量路径假设：

     - RMBench 侧：ROBOTWIN_ROOT / "XPolicyLab" 硬编码在 3 个 eval
       脚本、_install.sh、update_xpolicylab.sh、.devcontainer/*。
     - XPolicyLab 侧：policy/*/setup_eval_*.sh、eval.sh 用 BENCH_ROOT="$(cd 
       "${XPL_ROOT}/.." && pwd)" 反推 benchmark 根目录；utils/process_data.py 用
       __file__/../../env_cfg；utils/get_action_dim.sh 用
       ${ROOT_DIR}/XPolicyLab/...。

     目标（用户已确认）：XPolicyLab 变成平级独立仓库，通过环境变量定位；Mem_0 / 
     MemConflict 策略适配器继续留在 XPolicyLab 内。

     目标布局与统一约定

     - XPOLICYLAB_ROOT：指向 XPolicyLab checkout 的绝对路径（默认 $(dirname 
       $RMBench)/XPolicyLab，即平级仓库）。RMBench 用它找
       setup_policy_server.py、policy/<name>/、client_server/、utils/。
     - BENCH_ROOT：指向 benchmark（RMBench）根目录的绝对路径。XPolicyLab 的
       shell 脚本用 BENCH_ROOT="${BENCH_ROOT:-<旧 fallback>}" 读取；RMBench
       启动这些脚本时注入 BENCH_ROOT=$ROBOTWIN_ROOT。
     - 版本 pin：单一事实源 = scripts/update_xpolicylab.sh 里一个 XPOLICYLAB_REV
       变量（默认 11efb1dbd8fc03417c61a9c9840dd9baa1986640），clone 时 checkout
       到该 rev。

     ---

     - git 操作（实现阶段执行）：git rm --cached XPolicyLab、删除
       .git/modules/XPolicyLab 元数据；XPolicyLab 之后在 $XPOLICYLAB_ROOT 手动
       clone。

     方式运行，scripts/ 自动是 sys.path[0]，可 import xpolicylab_paths），导出：
     - resolve_xpolicylab_root(cli_value=None) -> Path：优先级
       cli_value（--xpolicylab_root）> $XPOLICYLAB_ROOT > ROBOTWIN_ROOT.parent /
       "XPolicyLab"；校验 root/setup_policy_server.py 存在，否则报错并提示
       clone 命令。

     A3. scripts/eval_policy_xpolicylab.py（客户端）

       checkout 根塞进 sys.path，使 from client_server.ws import WsModelClient
